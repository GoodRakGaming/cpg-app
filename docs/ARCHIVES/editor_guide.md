# Project cleanup summary

Я аккуратно реорганизовал корень проекта, чтобы уменьшить шум в файловом дереве и упростить навигацию для разработчиков и ИИ.

Что сделано автоматически (скрипт `scripts/organize_project.sh`):

- Созданы папки: `docs/`, `docs/phase_archive/`, `scripts/windows/`, `archive_misc/`.
- Перемещены все вспомогательные Markdown/документы в `docs/`.
- PHASE_* файлы перемещены в `docs/phase_archive/`.
- PowerShell-скрипты (`start-*.ps1`, `test-api.ps1`) перемещены в `scripts/windows/`.
- Оставлены в корне только ключевые элементы: `backend/`, `frontend/`, `README_MAIN.md`, `README.md`, `plan.md`, `LICENSE`.

Зачем это полезно:

- Меньше файлов на верхнем уровне = проще ориентироваться в проекте.
- ИИ и поисковые инструменты будут фокусироваться на `backend/` и `frontend/`.

Как отменить/изменить:

- Скрипт `scripts/organize_project.sh` можно открыть и изменить для обратной операции или запуска повторно (он перемещает файлы в новые папки).
- Если нужно вернуть отдельный файл в корень — просто переместите его обратно:

```bash
mv docs/QUICK_START.md ./
```

Дальше рекомендую:
- Добавить `docs/` в `files.exclude` и `search.exclude` в `.vscode/settings.json`, чтобы спрятать документацию из обозревателя и поиска.
- Сохранить текущую структуру в системе контроля версии (commit).
