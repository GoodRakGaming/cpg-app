# Контекст для сессии дизайна веб-интерфейса (Phase 9B)

Это самодостаточный бриф для нового чата. Задача этого чата — **не писать код**, а
спроектировать единый минималистичный визуальный стиль для веб-приложения (dashboard,
формы, таблицы), который потом реализует разработчик (в основном чате проекта) через
Tailwind CSS. Это отдельная сессия от Phase 9 (дизайн самого генерируемого PDF-документа
КП) — там уже всё решено и реализовано, см. `PHASE_9_KP_VISUAL_REDESIGN.md`.

---

## Проект

Commercial Proposal Generator — веб-приложение для создания и генерации PDF коммерческих
предложений (КП). Frontend на Next.js 16 / React 19 / TypeScript / Tailwind CSS. Развёрнуто
в проде: `cp.profstroi74.ru`. Пользователь — сотрудник компании "Профстрой" (не разработчик),
работает в интерфейсе каждый день: создаёт шаблоны юрлиц, готовит КП, проверяет версии,
генерирует PDF.

## Задача этой сессии

Сейчас интерфейс работает функционально (весь CRUD, версии, PDF-preview реализованы), но
визуально — это дефолтная Tailwind-вёрстка без единой системы: цвета/отступы/типографика
подобраны ad hoc по месту (`bg-blue-600`, `text-gray-700` и т.п. разбросаны по каждому файлу
отдельно), нет переиспользуемых компонентов, нет продуманной иерархии. Нужно:

1. **Проанализировать текущий интерфейс** — приложу скриншоты ключевых экранов отдельно
   (см. список экранов ниже). Оценить: что визуально шумно/непоследовательно, где не хватает
   иерархии, что можно упростить
2. **Спроектировать единый минималистичный стиль** — палитра, типографика, отступы/сетка,
   паттерны компонентов (кнопки, инпуты, карточки, таблицы, бейджи статусов, вкладки),
   применимые consistently на всех экранах
3. Отдать результат в формате, который можно **напрямую передать разработчику** (см. "Что
   нужно на выходе" ниже) — этот чат не имеет доступа к кодовой базе и не пишет код

## Экраны, которые нужно охватить

- `/login`, `/register` — формы аутентификации
- `/dashboard` — общий layout (шапка/навигация/контентная область)
- `/dashboard/templates` — список шаблонов (карточки/таблица)
- `/dashboard/templates/[id]` и `/dashboard/templates/new` — редактор шаблона: реквизиты
  юрлица, логотип, подписант, позиции по умолчанию, условия
- `/dashboard/proposals` — список КП (со статусами: черновик/финальный/архивирован)
- `/dashboard/proposals/[id]` — редактор КП с тремя вкладками: содержание (позиции, разделы,
  получатель), версии (таблица истории с восстановлением), PDF (превью/скачивание)

Формы шаблона/КП сейчас довольно длинные (много текстовых полей подряд) — если увидите,
как их визуально сгруппировать/upgrade — это тоже в фокусе сессии, не только цвет/шрифт.

## Технические ограничения (важно для дизайна)

- Реализация — **Tailwind CSS 4** (utility classes), не CSS-in-JS и не отдельная
  дизайн-система/библиотека компонентов. Результат должен ложиться в Tailwind-классы или
  минимальный набор кастомных CSS-переменных поверх Tailwind — не предлагайте сторонние UI-кит
  библиотеки (MUI, Chakra и т.п.), их не будем подключать
- Это обычное веб-приложение (не print/PDF, в отличие от Phase 9) — адаптивность нужна хотя бы
  под десктоп + планшет; мобильный — низкий приоритет (пользователь работает за компом)
- Next.js App Router, компоненты сейчас однофайловые (без разбиения на переиспользуемые
  `<Button>`/`<Input>`/`<Card>` и т.п.) — если предложите такое разбиение, это нормально
  принять как рекомендацию к рефакторингу, но не обязательное условие дизайна

## Что уже решено и с чем нужно определиться

- **Логотип/фирменный стиль клиента.** В Phase 9 для самого PDF-документа КП уже выбрана
  минималистичная нейтральная палитра в OKLCH (ink/text/muted/line + 1 акцентный цвет),
  Inter для текста. **Открытый вопрос для этой сессии:** должен ли веб-интерфейс (инструмент
  для сотрудника) визуально перекликаться с этими токенами документа КП (единый бренд), или
  это может быть отдельная, более "рабочая"/нейтральная палитра, заточенная под плотный UI
  с формами и таблицами, а не под клиентский документ? Обе позиции разумны — решите и явно
  обоснуйте выбор.
- **Тёмная тема.** Пока не реализована нигде в проекте. Нужна ли, или пропускаем в MVP этого
  редизайна?
- Сейчас нет `<Button>`/`<Input>`/`<Card>` компонентов — только повторяющиеся className.
  Дизайн-система может предложить 3-5 переиспользуемых паттернов компонентов, но не полную
  библиотеку — цель практичность, не абстракция ради абстракции.

## Что нужно решить в этой сессии (открытые вопросы)

1. Единая цветовая палитра (акцент, нейтральные, статусы success/warning/danger для
   бейджей КП: черновик/финальный/архивирован) — перекликается ли с токенами PDF или нет
   (см. выше)
2. Типографика — шрифт (веб-safe или Google Fonts подключаемый), масштаб размеров
   заголовков/текста/лейблов форм
3. Паттерн для длинных форм (шаблон/КП редактор) — как группировать блоки полей визуально
   (карточки/секции с разделителями/аккордеоны), особенно для опциональных блоков вроде
   банковских реквизитов
4. Паттерн для таблиц/списков (список шаблонов, список КП, таблица версий) — как показывать
   статус, действия (иконки/текстовые кнопки), пустые состояния
5. Нужна ли тёмная тема (см. выше)

## Что нужно на выходе (для разработчика)

1. **HTML/CSS-макеты ключевых экранов** — оформи как Artifact (можно несколько экранов в одной
   странице/табах: dashboard-layout, список + таблица, форма редактора, вкладки КП). Не нужно
   верстать один-в-один все 6 экранов пиксель-в-пиксель — достаточно показать паттерны
   (кнопки/карточки/таблицы/формы/бейджи) на 2-3 репрезентативных экранах, чтобы остальное
   можно было собрать по аналогии
2. **Design tokens** — цветовая палитра (с конкретными hex/oklch значениями под каждую роль:
   фон, текст, границы, акцент, success/warning/danger), шрифты, шкала отступов/радиусов
   скругления/теней — в формате, который легко завести в Tailwind (`tailwind.config` theme
   extend или CSS-переменные)
3. **Явные ответы на 5 открытых вопросов** выше — не оставлять их открытыми
4. **Компонентные паттерны** — для кнопок (primary/secondary/danger), полей ввода (обычное/с
   ошибкой/disabled), карточек, бейджей статуса, таблиц — краткое описание + пример разметки
   для каждого, не обязательно исчерпывающий каталог

## Рекомендованные skills для этой сессии

- **artifact-design** — обязательно перед тем как строить HTML-макеты. Даёт методологию
  элегантного дизайна интерфейсов (типографика, цвет, сетка, консистентность компонентов) —
  прямо подходит под задачу "получить чистую, профессиональную систему UI-паттернов"
- **dataviz** — пригодится для таблиц (список КП, список шаблонов, история версий): иерархия
  строк, выравнивание, консистентные отступы, паттерны для бейджей статуса — там есть готовые
  решения именно под табличные/списковые данные

Если увидишь в списке доступных скиллов что-то более подходящее под "аудит существующего UI и
построение единой дизайн-системы для веб-приложения" — используй по своему усмотрению, эти два
не единственно возможные, просто наиболее очевидно релевантные из известных на момент написания
этого брифа.
