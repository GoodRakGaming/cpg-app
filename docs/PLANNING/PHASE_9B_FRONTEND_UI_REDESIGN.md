# Phase 9B: Редизайн веб-интерфейса — итоги дизайн-сессии

**Статус:** ✅ реализовано и задеплоено (2026-07-17), поэтапно по экранам: токены/компоненты →
списки шаблонов/КП → редактор шаблона → редактор КП (мини-превью PDF) → NavRail.
**Источник:** отдельная дизайн-сессия (см. `PHASE_9B_FRONTEND_UI_DESIGN_SESSION_CONTEXT.md` — бриф).
Эта сессия отдала HTML/Artifact-макет — здесь зафиксирована суть, чтобы не зависеть от исходного
файла. Актуальный визуальный эталон — standalone HTML-файлы дизайн-системы в этой же папке.

## Ответы на 5 открытых вопросов (из брифа)

1. **Палитра** — общая с PDF-документом (Phase 9): единый акцентный цвет на весь продукт
   (документ + интерфейс = один бренд). Нейтральная шкала расширена (добавлены промежуточные
   уровни поверхностей, иначе карточка на 100%-белом фоне сливалась бы с фоном страницы) +
   добавлены `success`/`warning`/`danger` для статусов, которых в PDF нет и не может быть.
2. **Типографика** — Inter для UI-текста, JetBrains Mono для чисел/дат/ID (таблично выровненные
   цифры). Масштаб: заголовок 30/800 → секция 20/700 → текст 14/400 → лейбл 12.5px caps.
3. **Длинные формы** — карточки-секции с плоскими строками-полями (не одна длинная колонка
   инпутов). Закреплённая (sticky) панель сохранения внизу экрана со статусом
   («Сохранено · 13:41»), когда форма длиннее видимой области.
4. **Таблицы/списки** — поиск + фильтр-чипы + пагинация вместо голой таблицы. Статус — плоский
   тег (`border-radius: 6px`), не pill/капсула. Пустое состояние — иконка + текст + CTA-ссылка,
   не голая надпись.
5. **Тёмная тема** — не в этом релизе (работа днём в офисе, запроса не было). Рейл сделан как
   фиксированный по цвету элемент, не как переключаемая тема — полноценный dark mode остаётся
   кандидатом на отдельную итерацию.

## Design tokens (перевести в CSS-переменные проекта / `tailwind.config` theme.extend)

```css
:root {
  --ink: oklch(20% 0.02 260);
  --text: oklch(32% 0.014 260);
  --muted: oklch(54% 0.01 260);
  --line: oklch(91% 0.005 260);
  --surface-0: oklch(96.5% 0.004 260);   /* фон страницы */
  --surface-1: oklch(100% 0 0);          /* карточки/поверхности */
  --surface-inverse: oklch(21% 0.02 262); /* тёмные блоки (код, hero) */
  --accent: oklch(45% 0.12 250);
  --accent-soft: oklch(95% 0.02 250);
  --accent-on-dark: oklch(70% 0.14 250);
  --success: oklch(45% 0.13 150);
  --success-soft: oklch(95% 0.03 150);
  --warning: oklch(55% 0.14 80);
  --danger: oklch(50% 0.16 25);
  --danger-soft: oklch(95% 0.03 25);
  --radius-tag: 6px;
  --radius-control: 8px;
  --radius-nested: 10px;
  --radius-card: 14px;
  --shadow-card: 0 1px 2px rgba(15,15,25,.04), 0 6px 16px rgba(15,15,25,.06);
}
```

Эти же `--accent`/`--ink`/`--muted`/`--line` численно совпадают с токенами, уже реализованными
в `pdfService.js` (Phase 9) — единый бренд документ+интерфейс подтверждён по факту, не только
по декларации.

**Шрифты:** Inter (400/500/600/700/800) + JetBrains Mono (400/500/600), кириллица обязательна.
Подключать как `@font-face` (Google Fonts), не грузить с внешнего CDN в рантайме прод-сборки —
самостоятельно захостить `.woff2` в `public/fonts/`.

**Правило скругления (консистентность):** радиус вложенного элемента = радиус контейнера минус
его внутренний отступ, не ниже 6px. Шкала: 6 (тег) → 8 (контрол: кнопка/инпут) → 10 (вложенный
блок внутри карточки) → 14 (карточка/окно). Не использовать один и тот же радиус на всех уровнях
— на мелких элементах он визуально превращается в «овал».

## Компонентные паттерны для реализации

- **`<Button variant="primary|secondary|danger">`** — primary: `--accent` фон/белый текст, hover
  темнее (`oklch(38% 0.13 250)`); secondary: белый фон + `--line` бордер, hover — `surface-0`;
  danger: `--danger-soft` фон + `--danger` текст/бордер, hover — насыщеннее. Disabled — приглушённый
  серый, `cursor: not-allowed`. Радиус `--radius-control`.
- **`<Badge status="draft|final|archived">`** — плоский тег, не pill: draft = нейтральный серый,
  final = `--success`/`--success-soft`, archived = `--accent`/`--accent-soft`. Радиус `--radius-tag`.
- **`<Input>`** — обычный (бордер `--line`, focus → бордер `--accent` + `box-shadow` из
  `--accent-soft`), с ошибкой (бордер+текст `--danger`, подпись с описанием ошибки под полем —
  не просто красная рамка без объяснения), disabled (фон `surface-0`, текст приглушён).
- **`<Card>`** — `surface-1` фон, `--line` бордер, `--radius-card`, `--shadow-card` только на
  hover/интерактивных карточках (не статично на всех).
- **`NavRail`** — узкий (56px) боковой рейл, прозрачный по умолчанию (фон = фон страницы), при
  наведении на всю полосу — фон становится на ступень темнее; иконки-плитки внутри имеют свой
  отдельный hover-фон поверх фона рейла. Лого-плитка «П» — временная заглушка, **заменить на
  реальный знак Профстрой/КП Генератор** (SVG 24–28px) при наличии.

## Изменения по экранам (относительно текущей реализации)

- **Список шаблонов/КП** — добавить поиск + фильтр-чипы по статусу + пагинацию вместо простой
  таблицы; строки таблицы с hover-подсветкой; пустое состояние с иконкой-плейсхолдером и CTA.
- **Редактор шаблона** — разбить форму на карточки-секции (Основное / Реквизиты юрлица /
  Подписант / Позиции / Условия), закреплённая нижняя панель сохранения со статусом
  «Сохранено · HH:MM», когда контент длиннее экрана.
- **Редактор КП** — убрать вкладки полностью. Вместо вкладки «PDF» — живая кликабельная
  мини-превьюшка PDF сбоку (открывает полноэкранный просмотр по клику), кнопка «Скачать PDF» —
  в заголовке рядом со статусом. Вместо вкладки «Версии» — кнопка «Версии» в заголовке,
  открывающая историю версий (тот же список, что сейчас, просто не как постоянная вкладка).
  Позиции — как в шаблоне: строка с полями название/ед.изм(select)/кол-во/цена/сумма.

## Что НЕ делать сейчас

- Не подключать сторонние UI-кит библиотеки (MUI/Chakra и т.п.) — всё на Tailwind-классах или
  минимальном наборе CSS-переменных поверх него, как решено в брифе.
- Не реализовывать тёмную тему в этом заходе (см. п.5 выше).
- Финальный SVG-логотип — не блокер: пока временная монограмма «П», реальный логотип можно
  подставить позже без переделки токенов/компонентов.
